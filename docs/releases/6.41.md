# Meister 6.41

Stop redundant update work and preserve evidence when an upgrade fails.

- Check AI Homebrew clients before upgrading; current packages need no upgrade or sudo call. Failed inventory checks never start upgrades.
- Preserve current Homebrew downloads during normal Autofix, Homebrew, Healer and cache cleanup. Explicit disk-space emergencies retain their recovery behavior.
- Include failed package upgrades and failed post-update checks in the final report. Save raw failure evidence privately under `~/.meister/update-failures/`; an outdated cask is no longer described as a normal auto-update result.
- Install each release only when needed. Verify an already current CLI without reinstalling, preserve Homebrew links and caches, and leave the app alone for CLI-only releases.
- Reject stale or malformed app ZIPs before publishing a release.

The native app cask is unchanged. Existing update failures caused by application permissions or blocked macOS authorization still require that underlying issue to be resolved.

Validation: 259 Bats tests, 35 Python tests, 24 offline evaluation fixtures, shell lint and twin parity passed. The current-version installer path was also verified on the installed CLI without reinstalling.

Recap: Current packages are checked without reinstalling; failed upgrades retain downloads and visible diagnostic evidence.
