# Meister 6.37

Daily maintenance now bounds SmartInbox traversal and reuses successful Homebrew
metadata checks, reducing repeated work on large inboxes and frequent CLI starts.

- SmartInbox maintenance inspects up to 500 messages with 32 fresh model checks
  and a 60-second soft preview budget. It reports unfinished work and resumes
  from a stable message identity on the next run.
- Native confirmations receive model capacity before more local candidates are
  admitted. Every move retains current content, identity and protection checks.
  Full traversal remains available through `MeisterAI megasmart run --full`.
- Public Homebrew launchers cache successful metadata and Meister upgrade checks
  for 12 hours. `--deep`, `-a` and `BREW_UPDATE_MAX_AGE_SEC=0` force a fresh check.
  This replaces v6.36's mandatory network refresh on every invocation.
- The launcher, AI Updates and Homebrew maintenance share successful metadata
  within a run. AI clients still receive owner-based updates and verification.
- Identical npm executable paths are deduplicated across discovered prefixes.

Validation: 361 tests pass, plus 24 offline model-contract fixtures. An offline
13,424-message fixture uses 20 instead of 537 body-read batches (96.28% less
traversal work per maintenance run). Real Mail/model end-to-end speed is unmeasured.

Install: `brew update && brew upgrade maf4711/meister/meister`.

Recap: Bounded daily traversal, reliable continuation and cached startup checks;
full scans and forced refreshes remain available.
