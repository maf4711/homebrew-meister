# Meister 6.38

MeisterAI now honors `FM_HEAL_MODEL` and `FM_DIAGNOSE_MODEL` in
`~/.meister/config`. Previously the parser silently ignored these documented
settings, so `FM_HEAL_MODEL=system` could still use the default `auto` route and
escalate to Apple Private Cloud Compute.

Set both values to `system` to keep diagnostic model inference on-device:

```ini
FM_HEAL_MODEL=system
FM_DIAGNOSE_MODEL=system
```

Existing defaults remain unchanged: AI-Heal uses `auto`, read-only diagnosis uses
`system`, and `explain`, `today` and `suggest` use the on-device model. Explicit
config values override the environment. Invalid nonempty model values are
rejected before model invocation. Both CLI twins retain the shared config parser.

Seven regression tests exercise config parsing through actual routing with a
mock model. The local audit also verified real on-device generation through the
installed helper and CLI, and confirmed the installed app's Siri action metadata.
Spoken Siri invocation and PCC generation were not exercised.

Validation on the merged release candidate: 209 Bats tests, 124 Node tests,
35 Python tests, 24 offline model-contract fixtures, ShellCheck, Bash syntax and
twin parity all passed.

Install: `brew update && brew upgrade maf4711/meister/meister`.

The existing macOS app uses the updated CLI; this release contains no new app
binary. Full audit: [local Apple AI verification](../verification/2026-10-14-local-apple-ai.md).
