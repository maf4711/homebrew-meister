# Meister 6.51

**New: `meister sysdata` / `MeisterAI sysdata` — measure and slim System Data**

macOS shows local Time Machine snapshots, caches, VM disks, LLM models and Xcode/Simulator data as one opaque "System Data" bar. `sysdata` measures each contributor and slims them, CleanMyMac-style:

- Read-only preview by default, largest first, with the exact command for every candidate.
- Accurate measurement: `du -x` skips mounted simulator runtimes (on the test Mac `/Library/Developer/CoreSimulator/Volumes` alone would have added 73 GB twice); runtime image sizes come from `simctl runtime list -j`; nested folders are subtracted from their parents.
- `--do` runs only safe steps: thin local snapshots, empty DerivedData, delete unavailable simulators, prune uv/npm caches, `docker system prune -f` (no `-a`, no volumes) and `fstrim` in Colima so the freed VM blocks return to macOS.
- `--do --review` asks per item, default no, terminal only: ollama models (tags sharing the same data are marked), older simulator runtimes (newest per platform stays), LM Studio / Hugging Face / exo models and Xcode device support.
- Explicit command only; the automatic maintenance run is unchanged.

Validation: 9 new Bats tests with stubbed tools (preview changes nothing, `du -x` everywhere, safe steps only with `--do`, no deletion without a terminal, default-no per item, exit 64 for unknown options, twin dispatch). Full quality gate passed (349 Bats tests). Real preview on the development Mac: 525 GB measured in 49 s, 7 local snapshots.

Recap: System Data is now measurable per contributor and can be slimmed safely, with human review for models and runtimes.
