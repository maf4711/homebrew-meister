# Meister 6.46

Four warnings that came back in every run now heal themselves or can be closed with one command.

- A cask blocked by a real file at its target in Homebrew's `bin` folder is repaired. Homebrew never overwrites a real file, not even with `--force`, so a CLI that updated itself over its Homebrew link (such as `agy` from `antigravity-cli`) failed every upgrade. Meister moves the file aside when the cask declares exactly that target, reinstalls the cask, and puts the file back if the reinstall fails.
- A failed forced reinstall now logs Homebrew's error line.
- An AI app whose Homebrew cask has broken metadata is repaired with one forced reinstall and checked afterwards. Before, such an app (Ollama in the recorded case) stayed outdated while every run warned that it has no verified updater. An app in use is left alone; an app that was running is started again.
- System cache cleanup skips entries protected by macOS, such as `/System/Library/Caches/com.apple.kext.caches`, instead of reporting an incomplete cleanup in every run. Entries that really fail are named in the log.
- New command `MeisterAI docs accept` (`-n` for a preview) lists the new entries in the Documents root and accepts them as baseline. Maintenance still never accepts on its own.

Validation: 8 new Bats tests (301 in total); the full quality gate passed. Live on macOS 27.3: the Ollama repair took the app from 0.40.5 to 0.40.16 with Homebrew owning it; the `bin` repair was confirmed by hand with the same steps and has not yet run inside a full maintenance run.

Recap: blocked CLI casks and AI apps with broken cask metadata are repaired in the run, protected system caches no longer cause a warning, and the Documents baseline can be accepted with one command.
