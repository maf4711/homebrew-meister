# Meister 6.44

`meister purge` (and `MeisterAI purge`) now reclaims all the space macOS marks as purgeable, not only snapshots and old iCloud copies.

- New last step. After thinning local Time Machine snapshots and removing old local iCloud copies, `purge --do` asks the macOS purge service to release the rest. That is the same service macOS uses when the disk fills up. macOS decides what goes: caches, optimised media and local iCloud copies of any age, including files newer than `--days`.
- The preview shows the amount first, as `macOS can release: …`, and changes nothing.
- `--no-system` skips the new step. Runs limited to explicit paths skip it too.
- The step reports the bytes the purge service confirms; the measured free space after the run stays the result that counts. If the service or Swift is unavailable, purge says so and counts nothing as released.
- The apply hint and usage now name the CLI that was invoked (`MeisterAI purge --do` under MeisterAI).

Validation: 7 new Bats tests; the full quality gate passed. Live on macOS 27.3 with the shipped helper: 1 GB requested, 1.06 GB reported by the service, 1,053 MB more free space measured.

Recap: purge now lets macOS release everything it marks purgeable, shows the amount in the preview, and can be limited with `--no-system`.
