# Meister 6.47

The performance check now detects a Mac that is jammed rather than busy: high load with low CPU, because many processes wait at the same time.

- New step [8/8] in `Performance`. It warns when the 1-minute load average is above twice the core count, and names the five commands with the most runnable processes.
- One warning lists every command running 20 or more times (`PROCESS_SWARM_WARN_COUNT`, default 20), for example `mdworker_shared`, `CGPDFService` or `git`.
- One warning counts `git fsmonitor--daemon` processes, split into main repo, worktree, submodule and unresolved, and names the remedy: run batch git with `core.fsmonitor=false`.
- The step only reports. It sends no signal and stops no daemon.

Background: on 2026-11-18 a Mac with 14 cores showed load 172–209 at 54 % CPU. The cause was 260 fsmonitor daemons started by a repo-sync LaunchAgent that ran `git status` in every repository every 120 s. The LaunchAgent is fixed in Skill-Suite v0.9.25.

Validation: 15 new Bats tests, also under /bin/bash 3.2; the full quality gate and CI on Linux and macOS passed. A read-only live run took 0.2–0.5 s for about 2400 processes.

Recap: Meister now reports high load with low CPU, process swarms and git fsmonitor fleets, without changing anything on the system.
