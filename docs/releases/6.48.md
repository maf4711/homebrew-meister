# Meister 6.48

Meister now heals the maintenance warnings that have a known, safe remedy, instead of only reporting them.

- **git fsmonitor:** with 20 or more daemons and a global `core.fsmonitor=true`, Meister sets it to `false` and asks each daemon to stop through `git fsmonitor--daemon stop`. No signals. `MEISTER_FSMONITOR_HEAL=false` keeps the 6.47 report-only behaviour. Load and process-swarm checks stay report-only.
- **AI Updates:** an idle AI app without an unattended updater (Ollama, ChatGPT/Codex, Cursor) is handed to its official Homebrew cask (`--adopt`, else installed over it), verified and reported as FIX. An app in use is deferred to a later run.
- **Time Machine:** a configured, connected destination without any backup starts the first backup. A disconnected destination is silent, like a missing one.
- **Documents root:** new top-level entries are named once in a FIX and accepted into the baseline, with a backup of the previous baseline. Nothing is moved. `DOCS_ORDER_AUTO_ACCEPT=false` restores the warning.

Validation: 7 new Bats tests; tests now isolate the global git config (`GIT_CONFIG_GLOBAL`). Full quality gate passed (323 Bats, Python suites, offline FM evaluation).

Recap: four warning classes are now autohealed with verification; load and swarm stay report-only.
