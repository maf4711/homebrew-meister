# Meister 6.45

Cask upgrades blocked by a leftover artifact are repaired in the same run, and the preview flags of `heal`, `simfix`, `autofix` and `free` no longer change anything.

- Cask repair matches Homebrew's real output. When `brew upgrade --cask` stops with `It seems there is already an App at …` (also `Command Wrapper` or `Binary`), Meister removes the stale artifact inside that cask's Caskroom folder and reinstalls the cask once. Paths outside the Caskroom folder, and symlinks, are left alone.
- A repair is reported as a fix only after `brew outdated` no longer lists the cask. A formula that still fails keeps its warning, including tap-qualified names such as `maf4711/meister/meister`.
- `Auto-healed <n> broken cask(s)` now counts only casks with a missing app source.
- `-n` and `--dry-run` work at any position for `heal`, `simfix`, `autofix` and `free`. `free -n` prints the commands instead of running `sudo purge`.
- Unknown options and arguments end with exit code 64 and a message on stderr.
- The Spotlight check skips the read-only cryptex mounts under `/private/var/run/com.apple.security.cryptexd`, so it no longer reports four repairs that never happened.

Validation: 14 new Bats tests (293 in total); the full quality gate passed. The cask matcher was checked against the failure files of seven casks recorded on macOS 27.3. The repair itself has not yet run in a real maintenance run.

Recap: blocked cask upgrades are repaired and verified in the same run, preview flags are honoured, and unknown options fail with exit code 64.
